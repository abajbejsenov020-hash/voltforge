# Dualtron appearance and city plaza

The 23 indexed Dualtrons have a dedicated Blender refinement layer. Deck outlines, widths, depths, molded pads, printed graphics, service panels, bolts, rear footrests and controls follow the individually identified product reference. Compact Mini/Spider platforms and the broad X/Thunder platforms retain different proportions. The Thunder 3 also uses the owner's [top-view reference](https://www.maxblinker.com/img/cms/Produkty/Dualtron%20Thunder%203/dualtron-thunder-3-3.jpg) for its deck shape, grip print, folding cockpit and rear latch/footrest assembly.

These are photo-guided exterior reconstructions. Unmeasured deck dimensions, fine hardware and graphics remain approximate. The source/dimension distinctions are recorded in `artifacts/blender/expansion/premium/dualtron-refinement-sources.json`. The refinement code lives in `scripts/blender/expansion/premium/dualtron_refine.py`; the existing batch builder calls it only for Dualtron entries. Grip graphics and applicable EY4 displays use locally generated images embedded in the GLB and native files; older EY3 controls use geometric display details. Other brands' generated assets are checked against the recorded pre-update hashes.

**Setting → City plaza · Night** adds finite 3D paving, charging posts and cables, bollards, a canopy, trees, benches, buildings and glass-front interiors. Warm practical lights contrast with the night sky and cool fill. A Thunder 3 and Sur-Ron Ultra Bee are loaded from the existing Blender library at meter scale. The setting persists locally, and all existing settings remain available. This is real scene geometry: rotation changes foreground/background perspective, rather than moving over a flat background picture.

Static geometry is merged by material, foliage uses instancing, and background vehicles do not add shadow-map passes. Missing background assets produce a visible partial-setting status while the active build remains usable. Switching settings releases geometry, materials, textures, instanced buffers and decoded model bitmaps; late downloads cannot restore an abandoned scene.

Validation includes the native Blender reopen/export audit, the existing all-model geometry/assembly suite, and dedicated scene lifecycle tests. Node geometry checks use neutral texture placeholders because Node has no browser bitmap decoder. The all-23-Dualtron browser journey separately decodes every embedded image with the browser's bitmap decoder, checks renderer errors, and exercises exact model selection, deck/cockpit inspection, original photos, exploded views and restoration. Plaza browser checks cover desktop/phone layouts, persistence, setting transitions and failed model/HDR requests.

Final verification on 18 November 2026: all 434 Node tests, formatting and production build passed. All four focused Chrome journeys passed, covering every Dualtron plus the new plaza, failed background requests and the original garage. All 23 native/GLB reopen audits passed, and all 26 embedded images matched the authored RGBA artwork. The 223 unrelated asset hashes in the recorded baseline remained unchanged. The plaza contains 17 static mesh batches (20,416 triangles) plus two parked models; this is a geometry/resource count, not an FPS benchmark. Desktop/mobile captures are retained in `artifacts/scenes/city-plaza/`.
